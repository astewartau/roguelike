# Grid Roguelike

A dungeon-crawling roguelike in Rust, rendered with OpenGL and egui.

Time is neither turn-based nor free-running. Every action — a step, a swing, a
spell — has a **duration in game seconds**, and the clock jumps forward to the
next action that completes rather than ticking at a fixed rate
([src/time_system.rs](src/time_system.rs)). Stand still and the world stands
still with you; swing a heavy cursed axe and everything else gets a longer turn
while you recover. Fast enemies act twice before a slow player acts once, and
"how long does this take" is a real tactical variable rather than a flat
turn count.

**Status: in development.** It is playable end to end — pick a class, descend,
die, read your run back off the start screen — but the dungeon is endless and
there is no win condition yet. Balance is unsettled, and `cargo clippy` has a
standing backlog of warnings.

---

## ⚠️ You need to supply `assets/` before this will run

`assets/` is **not in the repository** (41 MB of licensed art and audio; the
32rogues license forbids redistribution). A fresh clone compiles fine and then
panics on launch:

```
thread 'main' panicked at src/render/mod.rs: Failed to load tileset
```

**[assets/README.md](assets/README.md) is the full specification** — exact
filenames, sprite-sheet dimensions and directory layout. The short version:

| Path | What | Where from |
| --- | --- | --- |
| `assets/32rogues/` | `tiles.png`, `rogues.png`, `monsters.png`, `items.png`, `animated-tiles.png` | [32rogues by Seth Boyles](https://sethbb.itch.io/32rogues) (free download) |
| `assets/sounds/` | `battle/`, `enemies/`, `interface/`, `inventory/`, `world/` | hand-curated subset; copy from an existing checkout |

Two traps worth knowing before you start:

- **The sheets' pixel dimensions matter.** Column counts are baked into the
  tile-ID maths, so a sheet of the wrong width renders the wrong sprite for
  everything instead of failing loudly.
- **`items.png` must be extended past stock to 27 rows**, because eleven
  ability icons are custom-drawn additions, regenerated by
  [`tools/make_tiles.py`](tools/make_tiles.py). Miss this and those hotbar icons
  silently draw garbage.

Sound is the forgiving half: missing audio files are skipped, so the game runs
silently rather than crashing.

## What's in the game

- **Four classes** — Fighter, Ranger, Druid, Necromancer — with their own
  abilities and starting kit.
- **A survival clock.** Hunger and fatigue drain in game time. Hungry stops HP
  regen; starving does armour-ignoring damage. Tired makes you easier to notice
  and your hits weaker; exhausted slows every action. Resting and sleeping
  fast-forward the world, which is how you recover and also how you get
  ambushed. ([src/systems/survival.rs](src/systems/survival.rs))
- **Component-based loot.** Items roll affixes as real components across
  Common / Magic / Rare / Legendary, with generated names at the top end.
  Curses are affixes too, and they bite through the systems they belong to —
  `CursedHeavy` through the time system's action speed, `CursedLoud` through
  attack noise. Unidentified items hide their affixes but apply them anyway.
- **A reactive fire ecosystem.** Fire lives on entities, not tiles: burning
  creatures, burning grass, oil puddles, fused oil barrels. It spreads to
  adjacent flammables in discrete game-time steps, grass burns out, wet grass
  dries first. ([src/systems/fire.rs](src/systems/fire.rs))
- **Hidden things.** Floor traps that must be spotted before they are stepped
  on, and side rooms sealed behind secret doors whose chest rolls loot as if it
  were two floors deeper.
- **Enemies that cooperate.** Support casters heal and haste their allies,
  bosses have signature abilities and summon minions, and some animals can be
  tamed by a Druid into companions.
- **Seeded runs.** Every run has a seed you can re-enter to replay the same
  dungeon, and finished runs append to `runs_history.jsonl` for the start
  screen's history panel. ([src/run_history.rs](src/run_history.rs))

## Building

### Prerequisites

Verified on Arch Linux. macOS and Windows are untested here.

The only native **build** dependency is ALSA: `alsa-sys` locates it with
pkg-config and the binary links `libasound.so.2`. Everything graphical is
`dlopen`ed at runtime instead of linked, so X11 and Wayland development
packages are *not* needed to compile.

```bash
# Arch Linux
sudo pacman -S rust pkgconf alsa-lib

# Ubuntu/Debian
sudo apt install cargo pkg-config libasound2-dev
```

At **runtime** the game loads your display stack dynamically. Any desktop
session already has these; they are listed for containers and headless CI:

- OpenGL: `libGL.so.1` / `libEGL.so.1`
- X11: `libX11.so.6`, `libX11-xcb.so.1`, `libxcb.so.1`, `libXcursor.so.1`,
  `libXi.so.6`, `libxkbcommon.so.0`, `libxkbcommon-x11.so.0`
- Wayland: `libwayland-client.so.0`, `libwayland-cursor.so.0`,
  `libwayland-egl.so.1`, `libxkbcommon.so.0`

### Build and run

Asset paths resolve against the **process working directory**, so run from the
repo root.

```bash
cargo run --release
```

### Tests

158 tests in `#[cfg(test)]` modules across 32 source files — dungeon
generation, combat, abilities, AI, survival, fire, identification, pathfinding,
FOV and run-history parsing. They run without opening a window.

```bash
cargo test
```

ALSA may print `unable to open slave` warnings under `cargo test` when no audio
device is available. They are noise, not failures.

### Profiling

`puffin` is an optional dependency behind the `profiling` feature, so a default
build carries no instrumentation and opens no port
([src/profiling.rs](src/profiling.rs)):

```bash
cargo run --release --features profiling
```

That serves a `puffin_http` endpoint on `127.0.0.1:8585`. Attach with
`puffin_viewer`:

```bash
cargo install puffin_viewer && puffin_viewer --url 127.0.0.1:8585
```

## Controls

### Moving and acting

| Input | Action |
| --- | --- |
| `W` `A` `S` `D` / arrow keys | move one tile |
| `Shift` + direction | attack in that direction |
| `Ctrl` + direction | interact in that direction (doors, chests) |
| `.` | wait |
| `C` | toggle sneak |
| `I` | toggle inventory |
| `]` | toggle grid lines |
| `F11` | toggle fullscreen |
| `` ` `` | toggle the dev menu |
| `Esc` | cancel targeting → close dev menu → close open window → pause menu |

### Hotbars

Three groups along the bottom. Drag an item or ability onto a slot to bind it;
right-click a slot to clear it.

| Keys | Bar |
| --- | --- |
| `Q` `E` `R` | ability bar (3 slots) |
| `1`–`5` | main bar |
| `Shift` + `1`–`5` | second bar |

### Mouse

| Input | Action |
| --- | --- |
| Left-drag | pan the camera |
| Left-click | click-to-move; path to and attack an enemy; bump a door or chest open; auto-loot on arrival |
| Left-click *while targeting* | confirm the target |
| Right-click | fire an equipped ranged weapon at the cursor |
| Right-click *while targeting* | cancel targeting |
| Scroll wheel | zoom at the cursor |

### Menus

Start screen, pause menu and dialogue: `W`/`S` or arrow keys to move,
`Space` or `Enter` to choose, `Esc` to back out.

## Project structure

Around 38k lines across 87 modules. Directories, not a file list:

| Path | Responsibility |
| --- | --- |
| `src/app.rs` | window, OpenGL context, winit event loop — no game logic |
| `src/engine/` | owns all simulation state and exposes it to the shell: state, init, the tick, floor transitions |
| `src/components.rs` | the ECS vocabulary — every component and item/affix data type |
| `src/systems/` | game logic by domain: AI, combat, fire, survival, inventory, identification, projectiles, webs, discovery, experience, item definitions |
| `src/systems/actions/` | what an action *does* once its duration elapses, applied by the time system |
| `src/time_system.rs` | the game clock and the action scheduler — the heart of the pacing model |
| `src/events.rs` | `GameEvent` queue; how VFX, audio and UI react without coupling to systems |
| `src/constants/` | every tuning number, grouped by domain. Systems read from here rather than inlining literals |
| `src/ui/` | all egui panels: inventory, hotbars, targeting, shop, loot, dialogue, message log, start/pause/game-over |
| `src/render/`, `src/renderer.rs`, `src/multi_tileset.rs`, `src/camera.rs` | instanced GPU tile rendering, sprite-sheet UV lookup, camera |
| `src/dungeon_gen.rs`, `src/grid.rs`, `src/spawning.rs` | floor generation, terrain, data-driven entity and NPC spawn tables |
| `src/fov.rs`, `src/pathfinding.rs`, `src/spatial_cache.rs`, `src/queries.rs` | visibility, A*, incremental blocking-position cache, shared read-only queries |
| `src/audio.rs`, `src/vfx.rs` | event-driven sound with distance falloff; one-shot visual effects |
| `src/run_history.rs` | seeded-run records and the `runs_history.jsonl` log |

Conventions for working in this codebase are in [CLAUDE.md](CLAUDE.md).
